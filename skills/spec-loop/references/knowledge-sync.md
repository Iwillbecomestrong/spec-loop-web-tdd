# 知识同步与状态收敛 (Knowledge Sync & Convergence)

无论任务从何处发起（`grill-me`、`spec-loop` 或普通开发），最终都必须统一经过本出口，把临时状态沉淀为项目的**单一真相（Single Truth）**。

---

## 一、信息分流矩阵

| 产物性质 | 目标归宿 | 说明 |
| :--- | :--- | :--- |
| **已确认的需求、接口与功能约束** | `SPEC.md` / `docs/specs/` | 需求与系统行为的唯一基准 |
| **已完成/正在推进的全局技术路线** | `PLAN.md` / `docs/plans/` | 总体执行计划与里程碑状态更新 |
| **已验证失败的方案、死胡同、教训** | `HISTORY.md` | 记录经验教训，作为后续 Web Plan 的负向约束 |
| **模块内部对外契约与依赖约束** | 对应子目录 `README.md` | 保证后续修改该模块时继续受门禁保护 |
| **过程草稿、临时 Review 原始日志** | `docs/work/` (按需归档或清理) | 临时中间态，不作为长期真相 |

---

## 二、收敛核验清单 (Convergence Checklist)

在宣布任务 DONE 之前，执行以下 5 项核验：
- [ ] 1. 所有生产代码改动均有自动化测试覆盖，全量回归测试 100% 绿灯；
- [ ] 2. `docs/work/` 中的临时方案已提炼并回写至正式文档，无残留悬挂矛盾状态；
- [ ] 3. `PLAN.md` 中对应的任务项状态已置为已完成；
- [ ] 4. 修改过的模块 `README.md` 描述与现行代码完全一致；
- [ ] 5. 若有排查踩坑，已记录至 `HISTORY.md`。
